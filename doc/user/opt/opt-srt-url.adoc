[.usage]
Format of SRT URL

Most SRT parameters and options can be grouped into an SRT Uniform Resource
Locator (URL), starting with `srt://`. The format of these SRT URLs is not yet
fully formalized. Different tools use slightly different formats.  The syntax
which is used by TSDuck is aligned with the format which is used in the
Haivision SRT library (see <<SRT-URL>>). Part of the description below is copied
from this specification. If an official standardized format is defined, TSDuck
will align to it.

The SRT mode can be specified explicitly using the `mode` parameter. When it's
not specified, then it is derived based on the host part in the URI and the
presence of the `adapter` parameter:

* Listener mode: if you leave the host part empty (adapter may be specified),
  e.g. `srt://:1234`.

* Caller mode: if you specify host part, but not adapter parameter,
  e.g. `srt://remote.host.com:1234`.

* Rendezvous mode: if you specify host and adapter parameter,
  e.g. `srt://remote.host.com:1234?adapter=my.addr`.

If the `mode` parameter is specified, the interpretation of the host and port
parts is the following:

* In listener mode, the host part is the local IP address to bind, e.g.
  `srt://10.10.10.100:5001?mode=listener`. The port part is the local port to
  bind (mandatory). The `adapter` parameter is an alternative for host part,
  e.g. `srt://:5001?adapter=10.10.10.100`.

* In caller mode, the host part is the remote IP address to connect to
  (mandatory). The port part is remote port to connect to (mandatory). The
  `port` parameter is the local port to bind. The `adapter` parameter is the
  local IP address to bind. The `bind` parameter is a shortcut to set adapter or
  port by specifying `bind=ADAPTER:PORT`. E.g.
  `srt://remote.host.com:5001?adapter=local1&port=4001&mode=caller`.

* Rendezvous mode is the same as caller except that the local port, if not
  specified by the port parameter, defaults to the value of the remote port
  (specified in the port part in the URI).

The following table lists all possible parameters in the SRT URL specification.
Some of them are not yet implemented by TSDuck. A bool value can be `yes`/`no`,
`on`/`off`, `true`/`false`, `1`/`0`.

|===

|adapter
|address
|-
