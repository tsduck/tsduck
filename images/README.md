# TSDuck image files

## TSDuck logo

The TSDuck logo is editable in `tsduck-logo.svg` (Scalable Vector Graphics).
No particular graphics editor was used. SVG is simply XML text with graphics directives
and the logo is simple enough to be hand-crafted using a text editor.

The SVG file is designed with a size of 1000x1000 but its structure is scalable by design.
Version of different sizes are exported as `.png` files. One `.ico` file was exported and
is used in resource files on Windows so that TSDuck executables and DLL's are marked with
the TSDuck logo.

The variants named `tsduck-extension` are proposed for TSDuck extension.
This is the same logo as TSDuck to emphasize the relationship with the parent project,
with a Persian Orange variation to outline the independence from TSDuck.

The PNG files of various sizes and the `.ico` files are generated using ImageMagick in
the script `convert-logo.sh`. However, ImageMagick is not able to correctly render the
transparent background of SVG files. Therefore, GIMP was used to manually export the
512x512 version of the PNG. Then, the script generates all other versions from this
largest PNG file.

## SVG files

The XML contents of SVG files were edited by hand.

Using `<text>` SVG tags with imported fonts works on most browsers but not with
GIMP, Emacs, or ImageMagick. In practice, the SVG format is correctly handled in
a few tools only. Therefore, in the logo, the name "TSDuck" was converted to a
SVG path using https://danmarshall.github.io/google-font-to-svg-path/ The font
file `gadugib.ttf` was uploaded to draw the text as a SVG path.

In the palette, the font rendering is not important and plain text is used in
the SVG file. Conversion to PNG was done once using GIMP.

## Draw.io files

Files `.drawio` are XML files which are used by the draw.io editing tool. It is
free and open-source. Editing can be performed online or using the local
application.

- Home page: https://www.drawio.com
- Online edition: https://draw.io

The Makefile rebuilds the PNG and (optionally) PDF versions of the diagrams.

The PNG and PDF files are generated by the makefile, using draw.io in command
line mode. The PNG files which are generated by draw.io are not optimized. They
are too large. The tool `optipng` is used as postprocessing to compress them.

Warning: draw.io is a JavaScript application based on Electron. It requires a
display server to connect to, even though it is used in command line mode
here. The `make` command fails if invoked in a remote ssh or headless
session. For this reason, rebuilding the PNG files from the draw.io files is not
part of the build process. The PNG files shall be regenerated using `make` each
time the draw.io files are modified using the draw.io GUI. Then, the PNG files
are stored in the repository.

Only the PNG files are used to build the documentation. The PDF files are built
as examples only, in `bin/doc`. They are not stored in the repository

### Installation on macOS

~~~
brew install --cask drawio
brew install optipng
~~~

### Installation on Ubuntu

~~~
sudo apt install -y snapd ttf-mscorefonts-installer optipng
sudo snap install drawio
~~~

If `.drawio` files are not correctly opened with the draw.io application, use
the following commands to define the assocation.

~~~
xdg-mime default drawio_drawio.desktop application/vnd.jgraph.mxfile
mkdir -p $HOME/.local/share/mime/packages

cat <<EOF >$HOME/.local/share/mime/packages/drawio.xml
<?xml version="1.0" encoding="UTF-8"?>
<mime-info xmlns="http://www.freedesktop.org/standards/shared-mime-info">
  <mime-type type="application/vnd.jgraph.mxfile">
    <comment>draw.io diagram</comment>
    <glob pattern="*.drawio"/>
    <sub-class-of type="application/xml"/>
  </mime-type>
</mime-info>
EOF

update-mime-database $HOME/.local/share/mime
~~~
